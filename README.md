# Fashion-MNIST CNN Interpretability Project

A beginner-friendly deep learning project built to answer one question: **not "how accurate can I make this model," but "can I actually see and explain what's happening inside it?"**

Most CNN tutorials train a model, report an accuracy number, and stop. This project does something different — it opens up a trained CNN and inspects it layer by layer: what filters it learned, how an image transforms as it passes through, and which exact pixels drive its final decision. It also tests two competing fixes for a real weakness the model has, and proves — with actual matching numbers, not just an explanation — that the underlying math of a convolution is fully understood, not just used as a black-box API call.

---

## Project philosophy

Every design choice in this project is driven by **"does this make the network easier to see inside,"** not "does this get the best possible accuracy." This is a deliberately different goal from a typical ML project, and it shows up everywhere:
- Small filter counts (8 → 16 → 32) so every single filter can be visualized at once
- A shallow network (3 conv blocks only) so the whole thing fits in your head
- `GlobalAveragePooling2D` instead of `Flatten`, specifically because it's the architecture that makes Grad-CAM (Step 8) work cleanly

## Step-by-step workflow

Each step below names exactly which file contains its code, which notebook (if any) runs it, and which saved image shows its result — so you can trace any claim in this README straight back to the file that produced it.

### Step 1 — Define scope & choose the dataset
**Decision, no code yet.** Fashion-MNIST was chosen specifically because it's small (28×28, grayscale, 10 classes), which keeps filters and feature maps easy to visualize and reason about — unlike a large, high-resolution dataset where "just look at it" stops being practical.

### Step 2 — Data loading & preprocessing
**File:** `src/data_prep.py`
**Function:** `load_and_preprocess_data()`
Loads Fashion-MNIST via Keras's built-in loader, normalizes pixel values from 0–255 integers to 0.0–1.0 floats, and reshapes images to include the channel dimension `Conv2D` requires: `(28, 28) → (28, 28, 1)`.
**No visualization** — this step is purely about getting the data into the right shape, verified by printed shape/dtype checks in the terminal.

### Step 3 — Exploratory Data Analysis
**Notebook:** `notebooks/01_EDA.ipynb`
**Functions:** `plot_sample_grid()`, `check_class_balance()`
Displays one example image from each of the 10 classes (a visual sanity check that labels match images), and confirms the dataset is perfectly balanced (6,000 images per class).
**Visualization:** rendered directly in the notebook (sample grid + class balance bar chart) — not saved to `reports/figures/`, since this step is purely exploratory.

### Step 4 — Build the CNN architecture
**File:** `models/01_baseline_cnn.py`
**Function:** `build_baseline_cnn()`
Defines the network: 3 convolutional blocks (8 → 16 → 32 filters), each with Batch Normalization, `padding='same'` to keep spatial dimensions predictable, and `GlobalAveragePooling2D` before the final classification layer instead of `Flatten`. Total size: only 6,442 parameters.
**No visualization** — this step only defines the architecture; `model.summary()` printed in the terminal is the only output.

### Step 5 — Train & evaluate the baseline model
**File:** `models/01_baseline_cnn.py` (the `main()` function)
**Shared code used:** `src/evaluate.py` (`evaluate_model()`, `plot_training_curves()`)
Compiles the model (Adam optimizer, `sparse_categorical_crossentropy` loss), trains for up to 15 epochs with `EarlyStopping`, then evaluates on the held-out test set.

**Result: 88.83% test accuracy.**

**Visualizations saved:**
- `reports/figures/baseline_curves.png` — training/validation accuracy and loss over epochs
- `reports/figures/baseline_confusion.png` — confusion matrix

**Key finding:** the confusion matrix revealed **Shirt** as the model's weakest class by far (precision 0.71, recall 0.66), heavily confused with T-shirt/top and Coat — three genuinely similar-looking clothing categories at 28×28 grayscale resolution.

### Step 6 — Filter visualization
**File:** `src/visualize.py`
**Functions:** `get_conv_layer_names()`, `visualize_filters()`
**Notebook:** `notebooks/02_interpretability.ipynb` (Cells 1–5)
Extracts and displays the actual learned weights from each of the 3 conv layers as small grayscale images. Layer 1's 8 filters are directly interpretable (simple edge/gradient patterns); Layer 2 and 3's filters are shown as grids (rows = filters, columns = input channels) to demonstrate how deeper layers combine multiple channels from the previous layer rather than looking at the raw image directly.

**Visualizations saved:** `reports/figures/filters_layer1.png`, `filters_layer2.png`, `filters_layer3.png`

### Step 7 — Feature map visualization
**File:** `src/visualize.py`
**Function:** `visualize_feature_maps()`
**Notebook:** `notebooks/02_interpretability.ipynb` (Cells 6–7)
Feeds one real test image (a Shirt, deliberately chosen since it's the hardest class) through the trained model and displays every conv layer's actual output activations — not the fixed filter weights (Step 6), but what those filters *produce* on this specific image. Also prints, per layer, how many of that layer's filters barely activated for this image.

**Visualizations saved:** `reports/figures/feature_maps_conv2d.png`, `feature_maps_conv2d_1.png`, `feature_maps_conv2d_2.png`

**Observed pattern:** Layer 1's feature maps still resemble the shirt's silhouette; Layer 3's are abstract and blocky — a direct visual demonstration of increasing abstraction with depth.

### Step 8 — Grad-CAM (+ two follow-up experiments)
**File:** `src/visualize.py`
**Functions:** `generate_grad_cam()`, `display_grad_cam()`
**Notebook:** `notebooks/02_interpretability.ipynb` (Cells 8–11)
Implements Grad-CAM: computes the gradient of the model's predicted class with respect to the last conv layer's feature maps, using that gradient to weight and combine the feature maps into a heatmap showing which pixels most influenced the decision.

**Visualizations saved:**
- `reports/figures/grad_cam_shirt.png` — a correctly-classified Shirt
- `reports/figures/grad_cam_misclassified_shirt.png`, `grad_cam_misclassified_shirt_2.png`, `grad_cam_misclassified_shirt_3.png` — three Shirts the model got wrong

**Key finding:** across all three misclassified examples, the model's attention concentrated on the collar/upper-shoulder region, but on shirts whose collar shape was less distinctive (boxier silhouette, heavier pattern, no clear V-neck), that same region led the model toward "Coat" or "T-shirt/top" instead. The model appeared to rely on coarse collar/silhouette shape rather than fine details like buttons.

**Follow-up experiment A — did more model capacity fix it?**
**File:** `models/02_delayed_pooling_cnn.py`
Added an extra conv layer before the first pooling operation, to test whether preserving fine detail longer would help the model notice buttons. **Result: it didn't help** — Shirt F1 slightly worsened (0.69 → 0.67). Saved: `reports/figures/delayed_pooling_curves.png`, `delayed_pooling_confusion.png`.

**Follow-up experiment B — did a stronger training incentive fix it?**
**File:** `models/03_class_weighted_cnn.py`
Kept the exact original architecture, but weighted Shirt 3x more heavily in the loss function during training. **Result: it worked** — Shirt recall improved from 0.66 to 0.75, F1 from 0.69 to 0.71, and overall test accuracy also improved slightly (89.15%). Saved: `reports/figures/class_weighted_curves.png`, `class_weighted_confusion.png`, and a re-run Grad-CAM comparison at `grad_cam_class_weighted_same_image.png`.

**Conclusion from both experiments together:** the Shirt confusion wasn't caused by the model lacking the *capacity* to learn a better feature — it was caused by nothing in training pushing it hard enough to actually prioritize learning one. Changing the training incentive (Experiment B) fixed it; adding more architectural capacity alone (Experiment A) did not.

### Step 9 — NumPy-from-scratch convolution
**Notebook:** `notebooks/03_numpy_from_scratch.ipynb`
**Functions:** `manual_conv2d()`, `manual_relu()`
Implements the convolution operation using only NumPy and plain nested loops — no Keras, no TensorFlow layers — then extracts the baseline model's **real trained weights** and confirms the manual implementation's output exactly matches Keras's actual computed output (`np.allclose`, difference on the order of `1e-7` or smaller, pure floating-point noise).

**Visualization saved:** `reports/figures/manual_vs_keras_conv.png` — side-by-side comparison, visually identical.

This step exists specifically to prove genuine understanding of what a `Conv2D` layer computes internally, rather than only knowing how to call it as an API.

Ties every step, file, and visualization together into one document.

## Key findings & lessons learned

- **A network's filters, feature maps, and decision-driving pixels can all be directly visualized** — "the model learned some features" doesn't have to stay an abstract claim.
- **Deeper layers don't see the original image** — they only ever see the previous layer's output, which is why filters become progressively more abstract with depth. This is the literal mechanism of how hidden layers work together.
- **More model capacity does not automatically fix a specific weakness** — capacity and training incentive are different levers, and this project directly demonstrated that by testing both against the same real problem.
- **`Flatten` isn't inherently dangerous** — the earlier lesson from a different, much smaller-dataset project was about parameter count relative to dataset size, not about `Flatten` itself being unsafe. This project's dataset was large enough that `Flatten` would have been fine; `GlobalAveragePooling2D` was chosen here for Grad-CAM compatibility, not out of necessity.
- **Interpretability tools double as debugging tools** — Grad-CAM didn't just explain the model, it generated a specific, testable hypothesis about *why* it failed, which then guided two concrete follow-up experiments.
